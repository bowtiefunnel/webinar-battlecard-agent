# Current state of the live n8n workflow (as of this writing)

The workflow has been toggled between "real" and "demo/fake" states repeatedly while
testing. **This doc describes what's actually live in n8n right now** — check it before
assuming the canvas matches [`n8n-workflows/battlecard-event-to-slack.ts`](../n8n-workflows/battlecard-event-to-slack.ts)
exactly, which represents the intended *real* end-state instead.

## Right now, in the live workflow

| Node | Current state | Why |
|---|---|---|
| Look Up Account (Simulated CRM) | **Fake** — a Set node with hardcoded Solstice Media data | No Supabase credential created yet |
| Bitscale Enrichment | **Fake** — a Set node with hardcoded enrichment data | No Bitscale credential or real Grid ID yet |
| Claude Battlecard Synthesis | **Real** — the actual AI Agent, calling Claude for real | Uses Gateway credits, no separate credential needed |
| Check Existing Battlecard Page | **Disabled** (passes input through unchanged) | No GitHub credential created yet |
| Commit Battlecard to GitHub | **Disabled** (passes input through unchanged) | Same |
| Post Battlecard to Slack | **Real** — posts to `#battlecard-demo` (`C0C5B6UN23U`) | Slack credential already existed and is bound |

A disabled node is a no-op passthrough, not skipped-and-broken — the chain still runs
end to end, it just means the GitHub commit never actually happens live right now.
Every sample page below was pushed to GitHub Pages **manually**, by taking the exact
`battlecardHtml` string the workflow generated and committing it by hand, to compensate
for the disabled auto-commit step.

## What's never been tested with real credentials

1. **Supabase** — the actual query (filter `accounts` by domain, limit 1) has never run
   against a real table. Standard, simple query; should work, but genuinely unverified.
2. **Bitscale** — the URL still has literal placeholder text
   (`REPLACE_WITH_GRID_ID`, `REPLACE_WITH_INPUT_COLUMN_UUID`). This isn't a "needs a
   credential" gap, it's a "will fail outright until you supply real values" gap.
3. **GitHub auto-commit** — disabled the whole time in this workflow. The same Contents
   API pattern (check-sha-then-PUT) is proven working in the separate
   `bowtiefunnel/competitor-battlecards` repo, but hasn't fired for real *here*.
4. **Workflow 2's button clicks** — only exercised via `test_workflow` with pinned/mocked
   data, never a real click on a real posted Slack message.

## Data-exposure note

The battlecard pages publish to `bowtie-funnel-Labs`, a **public** GitHub Pages site
that also hosts other public-facing resources (the GTM tools table, agent-models page,
etc.). Fine for this demo's fake account names — would leak real prospect/account
details publicly if pointed at real customer data without reconsidering hosting.
